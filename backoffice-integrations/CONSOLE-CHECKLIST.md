## 1. Два новых секрета Lockbox

Включить защиту от удаления. Значения нигде не присылать.

| Имя секрета | Кто получает `lockbox.payloadViewer` на самом секрете |
| --- | --- |
| `less-prod-backoffice-control-plane` | `service` (`ajefiauik875043qbf7r`) |
| `less-prod-backoffice-content-1` | `less-content-shard-1` (`ajeelrnlmu74tebrho6o`) |

В каждом секрете **два ключа**:

- `DB_PASSWORD` — новый пароль отдельной роли `backoffice_reader` в соответствующей БД.
- `BACKOFFICE_PROXY_SECRET` — новый секрет между служебным nginx и процессом чтения.

Каждое из четырёх значений сгенерировать отдельным запуском `openssl rand -hex 32`.
Не копировать пароли продуктовых ролей, токены Control Plane, личный PIN или секрет входного nginx.
Новые сервисные аккаунты, роли на каталог, бакеты и сертификаты Certificate Manager не нужны.

## 3. Машинные сертификаты — локально, не в консоли

Владелец запускает:

```sh
python3 /Users/kirilltitov/Work/Other/Sheets/infra/backoffice-integrations/issue-machine-certificates.py \
  --output-dir "$HOME/.less-pki/backoffice-transport-prod"
```

Скрипт запросит новый пароль и создаст отдельный машинный УЦ. Существующие корневой и
административный УЦ, личный сертификат и PIN не меняются. Закрытый ключ нового УЦ зашифрован,
остаётся в указанном каталоге; сохраните каталог и пароль для последующих выпусков и отзыва.
Закрытые ключи служб уже созданы непосредственно на ВМ и оттуда не извлекаются.
Скрипт подписывает три открытых запроса и сам доставляет **только открытые** сертификаты и CRL.
Это ещё не включает подключения и не перезапускает продукт.

Срок сертификатов — 90 дней, CRL — 7 дней. До истечения CRL владелец должен обновлять её
командой ниже; после установки подключений агент доставляет открытый файл на обе ВМ и
перечитывает конфигурацию служебных nginx. Автоматическое обновление не настроено.

```sh
export LESS_MACHINE_CA_DIR="$HOME/.less-pki/backoffice-transport-prod"
openssl ca -config "$LESS_MACHINE_CA_DIR/ca.cnf" -gencrl \
  -out "$LESS_MACHINE_CA_DIR/ca.crl.pem"
```

После создания секретов, правила и выпуска достаточно написать «готово»; значения не нужны.

## Последующая установка агентом

1. Проверить метаданные секретов, точечные права, правило и открытые сертификаты/CRL.
2. Доставить значения напрямую из Lockbox на соответствующую ВМ.
3. Создать `backoffice_reader` отдельно в `controlplane` и `less_content`: только CONNECT,
   USAGE и SELECT на используемых справочниками таблицах. Не давать роль владельца, доступ
   к другим БД, запись, миграции или SELECT на все будущие таблицы по умолчанию.
4. Запустить отдельный процесс `serve-backoffice` и nginx с общим сетевым пространством:
   процесс слушает только loopback, nginx проверяет УЦ, CRL и серийный номер клиента.
5. Подключить два источника в Backoffice по HTTPS; проверять серверное имя обязательно.
   Внутренние имена `control-plane.backoffice.internal` и `content-1.backoffice.internal`
   задаются через Docker DNS/extra_hosts, публичные DNS-записи не нужны.
6. Перед запуском перераспределить пределы контейнеров: сумма CPU не более 2 на каждой ВМ;
   оставить не менее 512 МиБ памяти системе. Не добавлять контейнеры поверх текущих лимитов.
7. Проверить справочники, реальный шард № 1, отказ без/с чужим/отозванным сертификатом,
   отказ записи ролью БД, закрытый публичный доступ и работу основного продукта.
8. Обновить применимые PLAN живыми доказательствами. Только после этого считать подключение готовым.
