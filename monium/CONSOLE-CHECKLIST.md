1. В рабочем каталоге `b1gk1vp06cum61i9d4fe` создать сервисный аккаунт `less-monium-writer`.
2. Назначить ему `monium.telemetry.writer` на этот каталог.
3. Выпустить API-ключ с областью `yc.monium.telemetry.write`. Скопировать **секретную часть ключа**, а не его ID.
4. Создать Lockbox `less-prod-monium`, поле `MONIUM_API_KEY` — секретная часть из шага 3. Включить защиту удаления.

Отдельные облачные машины, балансировщики и публичные порты для этого не нужны.
Официальная инструкция: [метрики приложений Monium](https://yandex.cloud/en/docs/monium/metrics/quickstart-app).

## Область первых измерений

Входящие HTTP-запросы Sheets API, Accounts, Control Plane и Backoffice API, включая внутренние вызовы,
проверки здоровья, отказы авторизации и ошибки. Изолированные процессы `serve-backoffice`
тоже измеряются и выделены отдельными именами сервисов. Время измеряется до завершения записи ответа;
при исключении до формирования ответа — до этого исключения. WebSocket после переключения протокола
не является HTTP-запросом: длительность сессии не смешивается с длительностью HTTP.

`http.server.request.duration` — распределение времени в секундах; `http.server.requests` — счётчик.
Метки: шаблон маршрута `http.route`, метод `http.request.method`, статус `http.response.status_code`.
Неизвестные маршруты объединены в `unmatched`; нестандартные методы — в `OTHER`.
Сырые URL, параметры, идентификаторы пользователей и страниц, заголовки, тела, cookie и секреты не отправляются.
Период отправки — 60 секунд. Сбой Monium не блокирует обработку пользовательского запроса.

Это серверные измерения: сеть браузера, сторонние OAuth/S3/SMTP и SQL-запросы по отдельности пока не измеряются.
Для этих участков нужны отдельные измерения зависимостей, их нельзя выдавать за уже покрытые серверной метрикой.

## Развёртывание

После проверки ресурсов доставить `deliver-monium.py` на обе машины и выполнить от root с `--secret-id ID`.
Он получает ключ через сервисный аккаунт ВМ, атомарно пишет `/etc/less/secrets/monium.env` с правами 0600
и не выводит значения. Не запускать `docker compose config` без `--quiet`: он раскроет переменные окружения.
Обязательно сохранять `OTEL_LOG_LEVEL=warning`: используемая версия swift-otel на уровне `info`
печатает значения переменных, включая заголовок авторизации. Значение `warn` эта версия не распознаёт.
Проверять журналы только с удалением секретов из вывода; полный вывод запуска экспортера не читать в чат.

После установки образов с измерениями включить настройки в основные Compose-файлы:

```sh
sudo python3 configure-compose.py common --apply
# На контентном шарде:
sudo python3 configure-compose.py shard --apply
```

Скрипт сохраняет `.before-monium`, добавляет файл окружения и имя каждого процесса,
проверяет конфигурацию без раскрытия значений. Это сохраняет отправку при следующих обычных
обновлениях сервисов, без необходимости помнить дополнительный параметр `-f`.
Подготовленные дополнения ниже оставлены как отдельное описание тех же настроек:

- common: `compose.services.yml` + `compose.content-shard.yml` + `compose.monium.yml`;
- backoffice: `compose.backoffice.yml` + `compose.backoffice-monium.yml`;
- shard: `compose.yml` + `compose.monium.yml`;
- внутренние читатели бекофиса: `compose.common.yml` + `compose.monium-common.yml` и
  `compose.shard.yml` + `compose.monium-shard.yml` из `infra/backoffice-integrations`.

Пересоздаются только API-контейнеры, без баз и миграций. Ограничения CPU/памяти сохраняются.
В Monium выбрать проект **default** — `folder__b1gk1vp06cum61i9d4fe`, cluster `production` и нужный сервис.
Два отдельных проекта с названием Less не используются. Рабочий раздел —
[Метрики](https://monium.yandex.cloud/projects/folder__b1gk1vp06cum61i9d4fe/explorer);
адрес с окончанием `/metrics` возвращает 404.
Проверить появление duration/count, затем сравнивать верхние перцентили и частоту ошибок по маршрутам.

Проверка состояния на каждой ВМ: `sudo python3 verify-monium.py`.
Она не печатает журналы и значения ключей; проверяет здоровье всех процессов, включение отправки,
уровень журналирования и отсутствие текущего ключа в просмотренных журналах.
Первый цикл после запуска иногда завершается превышением времени ожидания; отдельно проверять,
что последующие циклы отправляются, а время последней ошибки не обновляется.

Проверенный 06.10 запрос для максимальной длительности по маршрутам в миллисекундах
(без проверок здоровья; значение накоплено с запуска процесса):

```text
1000 * {project="folder__b1gk1vp06cum61i9d4fe", cluster="production", service="*", name="http.server.request.duration.max", "http.route"!="/health"}
```

`http.server.requests` — накопленный счётчик; не суммировать его значения по времени как число новых запросов.
Для частоты применять производную с обработкой сброса счётчика при перезапуске.
