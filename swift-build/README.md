# Компактные Swift-сервисы

Сборка сохраняет оптимизацию release и сведения, необходимые для читаемого аварийного стека:

```
-debug-info-format none -Xswiftc -gline-tables-only -Xcc -gline-tables-only
```

`-debug-info-format none` отключает автоматически добавляемый полный `-g` SwiftPM.
`-gline-tables-only` сохраняет функции, исходные файлы, строки и встроенные кадры.
Полные описания переменных и типов для интерактивной отладки дампа отсутствуют.
Секции затем сжимаются командой `objcopy --compress-debug-sections=zlib`.
Таблицы символов и сведения раскрутки стека не удаляются. Не применять `strip` к рабочему бинарнику.
Сжатие уменьшает файл на диске; повторное сжатие слоёв реестра может дать немного больший результат.

`SWIFT_BACKTRACE` явно включает неинтерактивный отчёт в stderr.
Docker сохраняет stderr отдельно от прикладного журнала сервиса.
При аварии сохраняйте `docker logs` и точный digest образа до удаления контейнера.

Проверка аварий выполняется отдельной программой внутри образа сервиса:

```
python3 swift-build/verify-crashes.py IMAGE --output /tmp/crash-proof
```

Программа не подключается к сети и не изменяет базы.
Она проверяет обычную и асинхронную ошибки памяти, встроенную функцию и `fatalError`.
Для проверки на Apple Silicon без эмуляции укажите `--platform linux/arm64` и ARM64-образ.
Перед выпуском x86-64 необходим такой же запуск на настоящем Linux/x86-64:
эмулятор может зависать после `fatalError`, даже когда стек уже напечатан.
Таймаут считается отказом проверки, а не успешным завершением.

Каталог `.build` каждого сервиса сохраняется отдельным кешем с архитектурой в имени.
Исходники, зафиксированные зависимости и компилятор остаются входами сборки SwiftPM.
