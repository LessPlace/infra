## CORS прямых загрузок — 05.10.2026

Причина отказа загрузки иконок, обложек и файлов: бакет `less` не имел CORS.
OPTIONS для PUT с Origin `https://less.place` возвращал 403 `AccessForbidden`:
`CORS is not enabled for this bucket.` Аватары работали, поскольку их загружает сервер Accounts.

На существующем бакете применено правило:

```sh
yc storage bucket update --name less --cors   'id=less-production-web,allowed-origins=[https://less.place],allowed-methods=[method-put,method-get,method-head],allowed-headers=[content-type,content-length,range],expose-headers=[ETag],max-age-seconds=300'
```

Команда задаёт весь список правил CORS: перед повторным применением сверить текущие правила,
чтобы не затереть последующие изменения. Настройка не выдаёт права на объекты: загрузка и чтение
по-прежнему требуют подписанных ссылок. Новых ресурсов, секретов и ролей не создавалось.

✅ Живые проверки Object Storage: предварительные запросы PUT/GET/HEAD с `https://less.place`
получают 200 и точный Access-Control-Allow-Origin; `https://devless.ru`, чужой сайт и DELETE
получают 403. Публичные read/list/config_read остались false, три правила политики сохранены.
⬜ Полный повтор загрузки иконки, обложки и файла в пользовательском сеансе проверяет владелец.
Изменена только конфигурация промышленного бакета: локальные компоненты не затронуты,
перезапуск не требуется; localhost:80 проверен отдельно.
